# 03.2. Executable worker analysis

Dependencies: 01–02 and 03.1. All code paths below are relative to the repository
root. This task owns the worker-summary foundation needed here; it does not depend
on completion of 05.

## Goal

Connect actual worker bodies to the existing symbolic memory analysis and checked
publication, execution, completion and join effects. An internal worker ledger or
a user-supplied result description cannot stand in for analyzing the body.

## Work

- [ ] Analyze each supported concrete worker definition using the existing memory
  pass and the semantic invocation from 03.1. Cover actual allocations, calls,
  transfers, branches, loops and cleanup; do not run latent body effects at closure
  construction or model asynchronous execution as an ordinary completed call.
- [ ] Bind scalar observations, supported aggregate projections and owned/shared
  capture views from the actual constructed environment. Preserve source and
  allocation identities through closure moves/copies and input/output descriptors;
  later parent mutations cannot alter worker inputs. Provide explicit binders for
  repeated environments, whose occurrence substitutions are completed in 03.3.
- [ ] Introduce the necessary checked worker summaries in the existing summary and
  transfer architecture. Carry entry requirements, scalar/provenance/instance/
  acquisition/worker binders, ordered conditional effects, surviving ownership,
  exits and proof dependencies. Preserve synchronization effects already supplied
  by 02; never replace them with only a scalar peak or infer exclusion from Send.
- [ ] Connect publication, body entry, completion and collection to these checked
  summaries. Preserve closure storage, spawn setup/publication overlap, local
  temporaries, shared views and retained result storage. Completion cannot occur
  from a manually fabricated result or discard remaining captured owners.
- [ ] Implement standard/vstd join-result handling, primitive-specific Result
  matching and proved-success extraction needed for workers. Connect success to
  the checked body, panic-free obligations and 01's environmental assumptions.
  Preserve functional postconditions; a functional external spec is not a memory
  summary and does not prove native join success.
- [ ] Keep waiting callers' storage live and retain completed results until their
  actual collection. Join transfers storage once, including returned shared links;
  dropping a handle cannot free an active worker. Reject excluded detach/failure
  behavior without silently removing charges.
- [ ] Compose existing supported helper ownership summaries during body analysis.
  Implement the summary substitutions necessary for worker lifecycle operations
  now, preserving actor and synchronization identities. Check representability
  before exporting effects; 05 extends this common interface with general helper
  synchronization/lifetime composition rather than creating a second summary form.
- [ ] Replace TODO-05 placeholders for body entry/completion with working consumers.
  Connect diagnostics and tests to production source analysis; retain an explicit
  boundary for still-missing global proof obligations.

## Completion criteria

Actual standard/vstd worker bodies supply checked ownership and ordered effects
to lifecycle transitions. Captures and returned allocations retain their identities
and charges across execution and join. Source changes produce corresponding
obligations, and missing body or result evidence is rejected. Fixed-worker execution
is connected; symbolic population integration remains explicitly assigned to 03.3.

## Validation

Exercise source programs with owned capture moves, delayed invocation, aggregate
inputs, conditional allocation, helper calls, early returns, owned/shared results
and delayed joins. Check waiting-frame and retained-result storage. Negative cases
must catch hidden extra allocations, stale capture inputs, lost results, duplicate
transfers, wrong instance/actor substitution and unproved join-success assumptions.

Tests must exercise source-derived checked effects and generated obligations;
hand-built ledger records or debug strings alone do not establish completion.
They may inspect intermediate results before the global rejection boundary but
must not disable that boundary or report a total memory proof. Run applicable
README checks and affected function-contract, closure, mode and erasure regressions.

## Remaining integration obligations

03.3 instantiates these interfaces over symbolic worker populations and completes
global shared ownership. 04 adds allocation-to-synchronization lifetime conditions;
05 composes these through general helpers and protected payload operations. 07
proves the simultaneous envelope under other workers' interference. Preserve the
required information now; no later task may have to recover phases from scalar peaks.
