# 03.4.2. Audit loops and shared ownership

**Second child of [03.4](03.4-worker-integration-and-completion.md).** Use the
[03.3 evidence](complete/03.3-symbolic-populations-and-shared-ownership.md)
to check that symbolic worker counts and shared allocation lifetimes follow
actual spawns, joins, clones and drops.

## Work

- [ ] Start with `every_peer_of_the_same_visit_must_retire` in `source/rust_verify_test/tests/resource/memory/worker_shared_ownership/occurrences/handoff.rs`. In its three-worker drain, binding the sibling’s joined result and dropping it passes the local checks. Inlining the drop as `drop(siblings.pop().unwrap().join().unwrap())` currently fails loop ownership composition. Reproduce both at the default solver limit, identify where their effects diverge, and check whether both can prove the same live-byte bound and reject the one-byte reduction.
- [ ] Check the loop-entry restriction for deferred backings. Compare a loop that clears its first deferred charge within the iteration with one where a peer still owns the buffer at the next iteration. Verify that every accepted bound includes the surviving allocation. Identify the precise diagnostic for any unsupported case.
- [ ] Trace zero iterations, repeated capture construction, partial drains, handle transfers and results retained across iterations. Match each outstanding handle to its publication and each strong alias to its allocation, including equal-sized buffers from different visits.
- [ ] Verify final release across workers, supported containers and nested payloads. Count handle slots and control storage separately from the backing. Change a spawn, join, clone or drop and check the resulting bytes or diagnostic. Cover excluded weak, raw, cyclic and leaking ownership paths.

## Done when

The symbolic-population and shared-ownership criteria in 03 have production paths
and named positive and negative regressions. Record the outcomes of both loop
comparisons. Judge any rejection against the approved operation matrix. An
in-scope discrepancy needs a verified fix before closure. For an excluded case,
record its scope and diagnostic. Use a numbered child for a substantial fix.

Start in `source/rust_verify_test/tests/resource/memory/worker_populations.rs`,
`source/vir/src/resource/memory/workers/populations.rs` and
`source/vir/src/resource/memory/workers/shared.rs`.
