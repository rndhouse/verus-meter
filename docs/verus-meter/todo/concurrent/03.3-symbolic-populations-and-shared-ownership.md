# 03.3. Symbolic populations and shared ownership

Dependencies: 01–02 and 03.1–03.2. All code paths below are relative to the
repository root.

## Goal

Connect symbolic worker counts and shared ownership to executable spawn/join
behavior. Preserve precise occurrences, capture inputs and shared backing across
supported loops, containers and acyclic nested worker trees.

## Work

- [ ] Instantiate worker-family and occurrence binders at actual publication and
  join events. Distinguish static sites from dynamic visits, and historical spawns
  from outstanding workers, running/waiting states and retained completed results.
  Counts must follow source transitions, not a user-maintained ghost counter.
- [ ] Generate initialization, transition and back-edge count/ownership obligations
  for supported symbolic loops, zero iterations, partial joins and handle storage
  in runtime containers. Preserve exact membership when collecting one result;
  no duplicate or nonexistent occurrence may be removed.
- [ ] Lift each repeated closure construction's scalar snapshots, aggregate views
  and ownership descriptors through checked occurrence substitutions. Preserve
  nested-parent coordinates and local loop contexts. One representative snapshot
  cannot describe differently constructed outstanding environments without proof.
- [ ] Connect checked worker effects from 03.2 to these symbolic populations.
  Retain per-state footprints and synchronization-instance/acquisition identities
  for later composition. Keep blocked storage and completed results represented;
  do not multiply an independent worst-case peak as the only available summary.
- [ ] Implement acyclic nested worker trees and supported ownership/handle transfers
  across workers and helpers. Generate join-safety obligations over actual actors,
  symbolic families and caller substitutions. Reject self/cyclic waits, execution
  past a pending join, detach and accounting-scope exit with unjoined descendants.
- [ ] Complete strong Arc new/clone/borrow/drop and checked input/output descriptors
  across workers, fixed fields and supported runtime containers. Compose imported
  views against the canonical root: local final release alone cannot reclaim
  backing. Analysis branching and ownership transfer must not create strong handles.
  Transferring a byte charge is not execution of a strong destructor.
- [ ] Prove global strong-reference conservation, including retained captures and
  results, and release each backing/payload tree exactly once at actual final
  destruction. Count model control storage and handles separately. Preserve one
  protected-root identity for 05's owning-payload updates; reject Weak/raw/cyclic
  ownership and other unmodeled reclamation operations.
- [ ] Keep spawn/publication transients, completion records and produced result
  storage in the corresponding states. A publication may overlap execution before
  spawn returns. Joining transfers ownership; waiting and handle loss cannot erase
  live worker storage.

## Completion criteria

Source-derived symbolic obligations account for every selected worker lifecycle
transition and shared reference across the required population forms. Counts,
capture snapshots and allocation identities correspond to executable events.
Nested workers and shared final release are checked globally within the covered
accounting domain, without silently assuming a schedule or serializing workers.

## Validation

Use source programs with symbolic zero/one/many workers, repeated constructions
with differing inputs, nested spawn loops, partial joins, returned buffers and Arc
aliases in captures/results/containers. Exercise handle transfers and blocked
callers. Check that completing a worker retains its result and dropping one alias
cannot free another worker's backing.

Negative cases must cover invented counts, repeated collection, stale occurrence
substitution, foreign shared roots, premature final release, lost descendants,
cyclic waits and excluded shared operations. Mutate executable spawn, clone, drop
and join operations without updating proof ghosts. Use the production source pass
to check resulting obligations; algebraic population tests are supporting evidence.
Run applicable README checks and affected loop, ownership and thread regressions.

## Remaining integration obligations

03.4 audits worker coverage. TODOs 04–06 attach lifetime conditions, compose general
helper effects and validate protocols using these identities and populations.
07 combines them into a global invariant and total byte envelope under interference;
local conservation alone cannot establish a synchronized memory bound. Keep the
contract rejection boundary until all required global obligations are connected.
