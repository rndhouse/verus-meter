# 03.3. Symbolic populations and shared ownership

Dependencies: 01–02 and 03.1–03.2. All code paths below are relative to the
repository root.

## Goal

Connect symbolic worker counts and shared ownership to executable spawn/join
behavior. Preserve precise occurrences, capture inputs and shared backing across
supported loops, containers and acyclic nested worker trees.

## Current implementation boundary

Commit `18ee45d8b` on `feature/concurrent-symbolic-analysis` connects nested
workers, captured join-handle transfers (including completion storage and imported
shared references), and loops that collect each worker within its iteration.
Repeated constructions use parent/local occurrence coordinates; nested captures
refer to the executing parent's inputs.

Commit `f32a74e7f` extends this to supported retained-worker Vec populations with
different construction inputs, exact loop membership and partial collection.
Each occurrence carries immutable input and conditional result descriptions.
Source tests check executable allocation sizes and reject explicit, lexical and
return-driven disposal of outstanding handles. Cleanup obligations observe the
actual exit state, after evaluating a return operand. The commit records the
full memory regression and supporting validation results.

Commit `9c57954c8` preserves several possible checked worker bodies at collection
joins, separately from the exact selected occurrence and its immutable result.
Local proofs cover finite mixed-family collections and separate symbolic
collections with differing results, partial joins and chained pop/unwrap/join
expressions. Every possible body retains its verification obligations; dropping
a selected handle remains a rejected detach. Its 19 population regressions pass.

Commit `babcd5a05` adds supported symbolic batches containing several worker
families per iteration in one Vec. Source tests preserve differing result sizes
through handle moves and partial collection, including stops within a batch;
enlarging an executable allocation in the second family fails its byte bound.
The existing representation composes block shifts and applies the pop law without
unfolding historical construction steps. All 20 population regressions pass at
the default solver limit, alongside 79 memory units, 44 examples and 2,395 VSTD
proofs. Formatting, strict Clippy and strict VSTD rustdoc also pass.

Commit `09414d872` preserves scalar result descriptions through retained worker
`join().unwrap()` operations, including partial collection, helper calls and
Boolean/signed results. Every possible checked body must supply a scalar
description; unknown results cannot borrow another family's value. Ordinary
functional proofs support input-dependent allocation bounds. Source mutations
reject false worker postconditions and insufficient byte bounds without adding
source-value assumptions. All 25 population tests pass: 24 in the 1,038-test full
memory run, plus the added functional-value regression checked separately.
The 80 memory units (one existing ignored), 44 examples, formatting and strict
Clippy for the affected library and test targets also pass.

Commit `61d9aa216` extends scalar tracing to explicit matches on checked worker
join results. The successful arm and unwrap share a payload projection. Commit
`0cb0da23b` checks disjoint strong-handle claims for fixed outstanding workers,
including a join handle transferred to another worker. At completion it checks
all outgoing aliases starting from actual result handles through acyclic backing.
A source regression retains 112 bytes through a sibling alias, rejects 111, and
verifies zero after its final drop. All 47 worker integration tests pass.

Commit `48f92bba3` lets a worker join a handle popped from a symbolic population
and pass the selected result back through its own join. Both joins retain the
original worker's scalar value or buffer size. The buffer regression verifies a
1,048-byte local bound, fails it when the executable allocation grows by one byte,
and verifies zero after drop. Dropping the selected handle in the collecting
worker still fails. All 1,042 memory integration tests and 44 resource examples pass.

Commit `3ce095231` supports moving a whole vector of pending handles into a
collecting worker. The publishing trace supplies the collection built at the
source capture. The receiver proves membership, logical length and backing
storage at loop entry and on every back edge. A symbolic drain discharges its
local obligations for arbitrary `n: u16`. Leaving one handle behind fails at
drop. In a separate two-worker test, returning the 64-byte buffer proves an
88-byte live bound. Returning the 1,024-byte buffer breaks that same bound.
The full 1,044-test memory run and a separately added strong-capture rejection
pass. Collections of workers with unaccounted strong aliases remain excluded.

Commit `fb68ae08a` shares the operation that transfers a collection's allocation
identities into the receiving thread's byte accounting. Capture uses the records
from construction. Return uses checked records describing what survived. Moving
a vector containing a boxed 64-byte array into a worker and returning it proves
96 bytes live after join, rejects 95 bytes, and proves zero after drop.

Commit `f5050d1c7` supports a worker joining part of a captured vector and
returning the rest to the thread that spawned it. The symbolic regression
proves the ordinary closure postcondition `result.len() == keep` for every
`keep <= n`. The checked transformation of the captured vector identifies
the surviving workers and transfers their join obligations to the caller.
Leaving one handle behind fails at cleanup. With two distinct workers,
swapping their insertion order keeps the returned count at one and breaks
the 88-byte bound for the selected buffer. The outer accounting domain still
rejects escaping workers. All 1,049 memory integration tests pass.

Commit `eddebc1bc` lets an ordinary helper take one handle vector by value
and return the same backing, including through another checked helper. For
vstd handles with scalar or unit results, the helper can join down to any
`keep <= n` and discard either outcome. The caller receives the surviving
workers and their join obligations. Native handles, including handles with
owning results, can pass through intact. In the two-worker regression the
caller proves 41 local bytes after one join, fails at 40, and reports an
outstanding handle if it skips the final join. All 1,053 memory tests pass.

Commit `a46da749c` lets a different thread join a worker that returns a vector
of outstanding handles. The worker's own handle carries its checked spawn
observation through the move. The receiving thread proves that it joins every
remaining worker for any `keep <= n`. Stopping its loop one handle early fails
at cleanup. With two producer handles of the same type, selecting the 64-byte
buffer proves an 88-byte local bound and zero after drop. Selecting the
1,024-byte buffer breaks the same bound. All 1,054 memory integration tests pass.

Joining native handles or taking ownership of a result inside an ordinary helper
still requires a checked description of the possible outcomes. For the symbolic
helper regression, changing the caller's drain
condition from `rest.len() > 0` to `rest.len() > 1` can exhaust the default
solver limit. Keep the rejection and improve the cleanup diagnostic for that
mutation. The fixed-size case already reports it directly.

Specialization of a captured collection in a drain loop currently uses a
publication outside a repeated visit and a construction expression closed over
source scalar parameters. More general publication contexts still need proofs.

The proof boundary now separates construction, collection transport and byte
accounting. Builders establish description properties; verified one-step laws
preserve the descriptions without inspecting them. Loop exits and membership
invariants share the same ownership transformation, while backing storage has a
separate checked bound. Recursive worker descriptions are accessed through
explicit specification queries, keeping ordinary allocation proofs independent
of their contents. These are compiler-generated observations of executable
events, not user-maintained counters or assumed population facts.

Commit `dfe9cf7f7` connects retained worker handles to a coordinator-owned
`Arc` with a flat payload. Each publication records the actual aliases moved
into the closure. A join consumes the selected worker's claim. For handle
vectors with a uniform capture count per root, Verus checks the relationship
between outstanding claims and vector lengths at loop entry and on back edges.
The coordinator can drop its own handle before draining the vector. A directly
returned `Arc` brings the same backing back into the caller's ownership.

The source regressions check a symbolic coordinator bound of `9 * n + 160`
bytes. Two workers capturing four aliases of one root fit a 70-byte current
bound after the parent drops its handle. Both a 69-byte bound and a source
mutation that gives the workers a second allocation fail. After a partial
drain and final join, a returned handle keeps 36 bytes live, and its destructor
reduces that to 4. All 1,057 memory integration tests pass.

Commit `8b6f31395` gives local drops and worker joins the same rule for
releasing shared backing. With the last directly tracked handle in a joined
worker and two workers still outstanding, the local check accepts 70 bytes
and rejects 69.

Commit `0d2e4297e` extends this rule to locally owned payload storage.
For workers sharing an `Arc<Vec<u8>>` with capacity `b`, the source test
establishes the coordinator's local bound of `9 * n + b + 160`. With two
workers and a 19-byte buffer, 107 live bytes suffice after dropping the
coordinator's handle. The final returned alias keeps 73 bytes live, and
dropping it leaves 6. Both one-byte reductions fail at their checkpoints.
With zero workers, dropping the coordinator's handle releases the buffer
immediately. All 1,058 memory integration tests pass.

Indexed payloads containing incoming storage or nested strong or worker
handles still require separate lifetime accounting. In a supplementary check
with both a vector and a box in the payload, the final 89-byte bound passed.
The 88-byte claim reached the default solver limit for symbolic worker count
and produced the budget diagnostic when the checkpoint specified one worker.

Commit `b8ced1e46` supports indexed joins whose workers return different
canonical roots. The coordinator checks the allocation identity in the selected
worker's result and preserves it across local moves and clones. In the source
test, two independent joins return the same 7-byte buffer. The combined live
bound is 63 bytes with two handles, 55 with one and zero after the last drop.
A 54-byte claim fails. Keeping the worker's distinct 19-byte buffer also breaks
the claimed bounds. Another regression drains `2 * n` workers that each capture
both roots and return one. Its local byte bound is `18 * n + 320`.
All 1,060 memory integration tests pass.

Commit `61d7cd5f3` resolves each worker family's returned `Arc` to its captured
allocation once per indexed join. The proof of the returned allocation's identity
and the accounting for references retained after the join use the same mapping.

Shared claims still require a root created outside repeatable coordinator loops
and another fixed handle at publication. The next population proof needs to
count each root's claims when workers in the same vector capture different
roots. In the symbolic drain above, changing each worker to capture only the
root it returns leaves the verifier unable to prove the selected drop or the
final byte bound. A separate variant keeps both captures per worker, drains to
one and joins the last handle outside the loop. It reaches the default solver
limit even with the intermediate byte checkpoint removed. Branching on the
changing handle vector length inside a drain also has an open collection
membership proof.

A different collecting actor or helper still needs to receive the reservation
along with the selected identity. Reusing a join site with surviving selected
handles needs a proof that preserves their distinct occurrences. The coordinator
can conservatively reserve backing until join. Establishing reclamation at the
actual last destructor in an arbitrary interleaving requires the execution-phase
proof. Keep this TODO open and retain the global concurrent-contract rejection.

## Work

- [ ] Instantiate worker-family and occurrence binders at actual publication and
  join events. Distinguish static sites from dynamic visits, and historical spawns
  from outstanding workers, running/waiting states and retained completed results.
  Counts must follow source transitions, not a user-maintained ghost counter.
- [ ] Generate initialization, transition and back-edge count/ownership obligations
  for supported symbolic loops, zero iterations, partial joins and handle storage
  in runtime containers. Preserve exact membership when collecting one result;
  no duplicate or nonexistent occurrence may be removed.
- [ ] Lift each repeated closure construction's scalar snapshots, aggregate views
  and ownership descriptors through checked occurrence substitutions. Preserve
  nested-parent coordinates and local loop contexts. One representative snapshot
  cannot describe differently constructed outstanding environments without proof.
- [ ] Connect checked worker effects from 03.2 to these symbolic populations.
  Retain per-state footprints and synchronization-instance/acquisition identities
  for later composition. Keep blocked storage and completed results represented;
  do not multiply an independent worst-case peak as the only available summary.
- [ ] Implement acyclic nested worker trees and supported ownership/handle transfers
  across workers and helpers. Generate join-safety obligations over actual actors,
  symbolic families and caller substitutions. Reject self/cyclic waits, execution
  past a pending join, detach and accounting-scope exit with unjoined descendants.
- [ ] Complete strong Arc new/clone/borrow/drop and checked input/output descriptors
  across workers, fixed fields and supported runtime containers. Compose imported
  views against the canonical root: local final release alone cannot reclaim
  backing. Analysis branching and ownership transfer must not create strong handles.
  Transferring a byte charge is not execution of a strong destructor.
- [ ] Prove global strong-reference conservation, including retained captures and
  results, and release each backing/payload tree exactly once at actual final
  destruction. Count model control storage and handles separately. Preserve one
  protected-root identity for 05's owning-payload updates; reject Weak/raw/cyclic
  ownership and other unmodeled reclamation operations.
- [ ] Keep spawn/publication transients, completion records and produced result
  storage in the corresponding states. A publication may overlap execution before
  spawn returns. Joining transfers ownership; waiting and handle loss cannot erase
  live worker storage.

## Completion criteria

Source-derived symbolic obligations account for every selected worker lifecycle
transition and shared reference across the required population forms. Counts,
capture snapshots and allocation identities correspond to executable events.
Nested workers and shared final release are checked globally within the covered
accounting domain, without silently assuming a schedule or serializing workers.

## Validation

Use source programs with symbolic zero/one/many workers, repeated constructions
with differing inputs, nested spawn loops, partial joins, returned buffers and Arc
aliases in captures/results/containers. Exercise handle transfers and blocked
callers. Check that completing a worker retains its result and dropping one alias
cannot free another worker's backing.

Negative cases must cover invented counts, repeated collection, stale occurrence
substitution, foreign shared roots, premature final release, lost descendants,
cyclic waits and excluded shared operations. Mutate executable spawn, clone, drop
and join operations without updating proof ghosts. Use the production source pass
to check resulting obligations; algebraic population tests are supporting evidence.
Run applicable README checks and affected loop, ownership and thread regressions.
