# 03.3. Symbolic populations and shared ownership

Dependencies: 01–02 and 03.1–03.2. All code paths below are relative to the
repository root.

## Goal

Connect symbolic worker counts and shared ownership to executable spawn/join
behavior. Preserve precise occurrences, capture inputs and shared backing across
supported loops, containers and acyclic nested worker trees.

## Current implementation boundary

Commit `18ee45d8b` on `feature/concurrent-symbolic-analysis` connects nested
workers, captured join-handle transfers (including completion storage and imported
shared references), and loops that collect each worker within its iteration.
Repeated constructions use parent/local occurrence coordinates; nested captures
refer to the executing parent's inputs.

Commit `f32a74e7f` extends this to supported retained-worker Vec populations with
different construction inputs, exact loop membership and partial collection.
Each occurrence carries immutable input and conditional result descriptions.
Source tests check executable allocation sizes and reject explicit, lexical and
return-driven disposal of outstanding handles. Cleanup obligations observe the
actual exit state, after evaluating a return operand. The commit records the
full memory regression and supporting validation results.

Commit `9c57954c8` preserves several possible checked worker bodies at collection
joins, separately from the exact selected occurrence and its immutable result.
Local proofs cover finite mixed-family collections and separate symbolic
collections with differing results, partial joins and chained pop/unwrap/join
expressions. Every possible body retains its verification obligations; dropping
a selected handle remains a rejected detach. Its 19 population regressions pass.

Commit `babcd5a05` adds supported symbolic batches containing several worker
families per iteration in one Vec. Source tests preserve differing result sizes
through handle moves and partial collection, including stops within a batch;
enlarging an executable allocation in the second family fails its byte bound.
The existing representation composes block shifts and applies the pop law without
unfolding historical construction steps. All 20 population regressions pass at
the default solver limit, alongside 79 memory units, 44 examples and 2,395 VSTD
proofs. Formatting, strict Clippy and strict VSTD rustdoc also pass.

The proof boundary now separates construction, collection transport and byte
accounting. Builders establish description properties; verified one-step laws
preserve the descriptions without inspecting them. Loop exits and membership
invariants share the same ownership transformation, while backing storage has a
separate checked bound. Recursive worker descriptions are accessed through
explicit specification queries, keeping ordinary allocation proofs independent
of their contents. These are compiler-generated observations of executable
events, not user-maintained counters or assumed population facts.

Retained populations still exclude shared captures/results. General helper and
nested retained-population transfers, scalar join-result tracing, global
strong-reference conservation and actual final destruction remain unfinished.
Preserve the existing rejection of unsupported paths; do not substitute one mutable capture
snapshot or treat transport into a forest as destruction. Concurrent contracts
still require the global proof boundary. This does not complete 03.3; all work
and completion criteria below remain required.

- [ ] Keep spawn/publication transients, completion records and produced result

## Completion criteria

Source-derived symbolic obligations account for every selected worker lifecycle
transition and shared reference across the required population forms. Counts,
capture snapshots and allocation identities correspond to executable events.
Nested workers and shared final release are checked globally within the covered
accounting domain, without silently assuming a schedule or serializing workers.

## Validation

Use source programs with symbolic zero/one/many workers, repeated constructions
with differing inputs, nested spawn loops, partial joins, returned buffers and Arc
aliases in captures/results/containers. Exercise handle transfers and blocked
callers. Check that completing a worker retains its result and dropping one alias
cannot free another worker's backing.

Negative cases must cover invented counts, repeated collection, stale occurrence
substitution, foreign shared roots, premature final release, lost descendants,
cyclic waits and excluded shared operations. Mutate executable spawn, clone, drop
and join operations without updating proof ghosts. Use the production source pass
to check resulting obligations; algebraic population tests are supporting evidence.
Run applicable README checks and affected loop, ownership and thread regressions.
