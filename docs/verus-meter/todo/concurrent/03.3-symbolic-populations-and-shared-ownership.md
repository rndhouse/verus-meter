# 03.3. Symbolic populations and shared ownership

**Next is 03.3.3.** Prove which executable drop releases the last strong reference across workers, including when that drop happens before join.

## What works today

The implementation branch tracks individual workers in supported symbolic spawn and join loops, including partial drains, nested workers, and transfers of handle collections. In the publishing thread, an indexed join can identify which captured `Arc` a worker returned. Its identity proof and byte accounting use the same mapping. The publishing thread can now drain a vector whose workers hold different allocations or different numbers of aliases. After a partial drain it can prove which allocation the last handle returns.

Implementation commit `13c440bce` closes 03.3.0 with 1,063 passing memory integration tests. The earlier test cases, limitations and commit-by-commit evidence are preserved in this document at main commit `cbf48b8bd`.

In `06a1e3c73` and `c324acdb8`, a worker can receive a handle popped from a mixed collection and return the selected allocation. A loop can keep results from successive visits to the same join alive together. Swapping which buffer survives breaks the smaller byte bound. The completed 03.3.1 document records validation and the remaining whole-collection restriction.

In `6c062584d`, a waiting worker retains its buffer through a nested join, and a publisher can overlap its child before spawn returns. The completed 03.3.2 document records the byte boundaries and coverage.
