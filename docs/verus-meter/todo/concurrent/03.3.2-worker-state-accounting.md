# 03.3.2. Account for each worker state

**Depends on 03.3.0–03.3.1.** A worker may start before spawn returns, block while holding storage, or finish while its result is still waiting to be joined. Connect the worker effects verified in 03.2 to each occurrence in these states.

## Work

- [ ] Distinguish workers ever spawned from workers running, waiting, completed with retained results, and joined. Advance the state only when the corresponding executable event occurs. Preserve nested worker coordinates and join dependencies.
- [ ] Carry the live-byte expression for each state, including spawn temporaries, captures, blocked callers, completion records and produced results. Account for publication overlapping execution. Transfer the result at join and keep the caller at a pending join until its child completes.
- [ ] Preserve the synchronization instance and acquisition identity attached to each worker effect for later composition. Keep per-state storage available to 07 so it can use synchronization to constrain overlap.

## Done when

Use a source program in which a worker owns a buffer while waiting for a nested child, then returns the buffer to its own joiner. Check that the buffer remains charged during the wait, while the completed result is retained, and after transfer until the owner drops it. Increase the executable buffer size by one byte against a tight local bound and require the corresponding failure. Check that assuming progress past a pending join cannot discharge a lifetime obligation.

Cover overlapping publication and execution without assuming a schedule, and distinguish zero workers from a completed worker with an uncollected result. State-specific checks must run with the overall concurrent-contract rejection still in place.

Start in `source/vir/src/resource/memory/workers/execution.rs`, `source/vir/src/resource/memory/workers/waits.rs` and `source/rust_verify_test/tests/resource/memory/worker_execution.rs`.
