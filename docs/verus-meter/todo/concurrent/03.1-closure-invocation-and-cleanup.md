# 03.1. Closure invocation and cleanup

Dependencies: 01–02; existing foundations recorded in 03. All code paths below are
relative to the repository root.

## Goal

Represent supported worker invocation through Rust source semantics without
requiring one exact compiler-generated FnOnce wrapper shape. Preserve the ownership
and cleanup obligations currently guarded by that validation.

## Work

- [ ] Replace exact wrapper-shape admission with a semantic invocation description:
  transfer the owned environment into execution, access captures according to the
  closure's call behavior, retain returned ownership, and destroy remaining captures
  at the correct source-semantic boundaries. Distinguish a borrowed body returning
  from destruction of its enclosing owned environment.
- [ ] Retain compiler-derived type, capture, move, temporary-scope and cleanup facts
  where useful. Normalize them at the frontend boundary; the memory analysis must
  not depend on exact wrapper local numbers, basic-block layout or shim call syntax.
  Do not replace established compiler facts with a parallel Rust ownership checker.
- [ ] Preserve precise executable capture layouts after proof erasure, source-body
  identity, partial moves and construction-time descriptors. The environment's
  inline charge remains separate from the ownership of its captured descendants.
- [ ] Account for each remaining capture exactly once, in Rust's applicable drop
  order, including explicit drops, early returns and result transfers. Preserve
  synchronization identities and release ordering when captures carry effects.
  Last use or StorageDead alone cannot establish destructor execution.
- [ ] Preserve the selected panic/failure boundary. Normal completion must not
  discard unwind obligations or assume panic freedom; expose the requirements for
  03.2 to discharge under 01's policy.
- [ ] Replace adapter-specific metadata, consumers, trace assertions and tests with
  semantic obligations. Review the earlier adapter dependencies as well as the
  dedicated validator; removing only its latest commit is insufficient. Preserve
  unrelated capture, shared-root, call-site and cleanup analysis.
- [ ] Document which source rules and trusted frontend facts justify the normalized
  invocation. Retain explicit rejection for genuinely missing ownership/effect
  evidence. Deleting a check without replacing its soundness obligation is not a fix.

## Completion criteria

Supported invocation has a single semantic interface usable by worker-body
analysis. The exact generated wrapper is no longer an admission requirement.
Ownership of the environment, remaining captures and results is conserved, with
no extra compiler-wrapper storage charges introduced into the source memory model.

## Validation

Use source closures that borrow their captures during invocation, consume captures,
return owned captures, partially move aggregates, and retain unconsumed captures
until cleanup. Include runtime Copy environments, nested captures and erased proof state
within the supported Verus surface. Verify early-return and drop ordering; negative
cases must catch lost/double-released ownership and missing required evidence.
Inspect semantic effects through the production frontend, not a required MIR shape.
Existing unsupported closure forms remain explicit exclusions.

Run applicable README checks and affected closure, reference, mode and erasure
regressions. Use focused internal tests only for distinct normalization invariants.

## Remaining integration obligations

03.2 consumes this invocation in actual body analysis and connects completion/join.
04 establishes allocation containment under synchronization; 07 checks global byte
bounds. Keep the concurrent-contract rejection boundary intact until its required
obligations are implemented. Completing this task alone does not enable workers.
