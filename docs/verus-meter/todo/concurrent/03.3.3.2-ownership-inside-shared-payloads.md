# 03.3.3.2. Ownership inside shared payloads

**Follow 03.3.3.1 under [03.3.3 — Prove final release](03.3.3-shared-final-release.md).** Dropping the last outer `Arc` destroys its payload. An inner buffer can still have an owner elsewhere, and a worker whose handle was stored in the payload can still be running. Fixed worker cases already follow nested strong handles. Extend that accounting to handles and results kept in supported collections.

## Work

- [ ] Preserve ownership of a buffer supplied by a caller, including across helper calls, worker captures, collection slots and returned results. Follow the existing convention for incoming storage so the same buffer is charged once and its release is visible in the domain that pays for it.
- [ ] Track the strong handles in each supported acyclic payload. Two fields may point to the same inner allocation. Destroying the payload drops both handles, and releases the inner backing only when its own last strong handle drops. Preserve its identity for later synchronization proofs.
- [ ] Carry the join obligation of a worker handle inside a payload through supported transfers. Dropping the payload while it still owns an outstanding handle must produce the detached-worker diagnostic. A checked join must account for any storage retained by its result.

## Done when

Use executable allocations, clones, moves, joins and drops. Move aliases of an outer `Arc` into workers, store their join handles in a vector, and follow the payload through the joins and final drop. Exercise a caller-supplied buffer and a payload with two fields pointing to the same inner buffer. Check the tight live total and the drop in bytes after final release. Keep one extra inner clone outside the payload and require the early-release claim to fail. Include a case where a worker performs the last drop before its own join, and check the parent's 89-byte versus 88-byte vector-plus-box case.

Exercise both a transferred worker handle that reaches its join and an outstanding handle lost at destruction. At the default solver limit, require the relevant byte or ownership diagnostic for each negative case. Positive cases must discharge the local obligations needed by 07. The parent's exclusions for weak references, raw ownership, cycles and unmodeled reclamation still apply.

Start with `source/vir/src/resource/memory/accounting/transport.rs` for the current indexed-payload restriction, `source/vir/src/resource/memory/shared/phases.rs` for fixed nested ownership, and `source/vir/src/resource/memory/heap.rs` for executable destruction. Extend the indexed payload cases in `source/rust_verify_test/tests/resource/memory/worker_shared_ownership.rs`.
