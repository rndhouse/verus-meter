# 03.3.3.1. Allocations across loop iterations

**Next under [03.3.3 — Prove final release](03.3.3-shared-final-release.md).** A loop can clone one buffer for all workers or allocate a fresh buffer on every visit. The existing repeated-allocation test joins both workers before the next visit. This task covers workers and returned aliases from different visits that remain live together.

## Work

- [ ] Give each execution of the allocation site a distinct identity. Reuse the checked loop and enclosing worker coordinates where applicable. Every clone of the same allocation must keep its identity, including when one iteration publishes several workers.
- [ ] Carry that identity from capture through handle collections, joins and retained results. When a result drops, reconcile its strong references against the allocation from its own visit. Cover publication that transfers the last handle held by the publisher.
- [ ] Derive the buffer contribution from the distinct live allocations. Preserve symbolic worker counts and buffer sizes, and account separately for handles, control blocks and collection storage.

## Done when

Exercise two source programs that retain their workers' results until collection. In one, each worker returns a clone of a single buffer allocated before the loop. In the other, each returns a fresh buffer allocated inside the loop. For `n > 0` workers and capacity `b` bytes per buffer, establish buffer contributions of `b` and `n * b`, respectively. Use symbolic function budgets and fixed checkpoint values where required by the current contract syntax. Include overhead in each asserted total. Cover zero workers according to the actual lifetime of the publisher's handle.

With two fresh, nonempty buffers alive, a budget allowing only one buffer must fail. Drop one result while keeping the other and check the remaining bytes. In the shared case, dropping one result must keep the single backing live. Require a budget diagnostic at the default solver limit for a one-byte reduction at a live checkpoint. Positive cases must pass the local obligations before the global proof in 07.

Start with `source/vir/src/resource/memory/workers.rs` for worker occurrence identities and `source/vir/src/resource/memory/workers/shared.rs` for the current restriction on indexed aliases of repeated allocations. Extend the source cases in `source/rust_verify_test/tests/resource/memory/worker_shared_ownership.rs`.
