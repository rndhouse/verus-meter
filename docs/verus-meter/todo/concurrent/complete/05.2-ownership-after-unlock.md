# 05.2. Ownership after unlock

Build on 05.1. Follow a box that one worker puts in a shared vector and a second
worker removes, carries past unlock and returns. Its allocation can outlive both
the mutex and the worker. The same box must have one owner throughout.

## Work

- [x] On a successful pop, connect the selected element and its owned descendants
  to the worker’s result. Remove that ownership from the protected vector while
  preserving any remaining reservation. An empty pop transfers no allocation.
- [x] Carry the result through worker completion and successful join using the
  existing result machinery. Account for it while the worker is complete but
  unjoined, after join in the receiving thread, and until its actual drop.
  Distinguish a failed join from a successful join returning `None`.
- [x] When the thread retaining the mutex observes its contents after join, or
  successfully extracts them from a unique `Arc`, use the contents left by the
  workers. Keep the returned box separate from every element still in the vector.

## Completion evidence

- [x] Exercise both pop outcomes. On the nonempty path, drop the last mutex owner
  while the joined result stays live. Prove the local current-byte bound there,
  reject one byte less, then verify the reduction when the result drops.
- [x] Leave distinguishable allocations in the vector so that returning one box
  and extracting the remaining contents checks which allocation moved. Compare
  the charges before unlock, at completion, and on receipt using the existing
  worker checks. A bound which omits the unjoined result must fail.

Start with `source/vir/src/resource/memory/workers/results.rs`,
`source/vir/src/resource/memory/shared/extraction.rs` and the shared payload
regressions from 05.1. Use the existing source rules for vector storage.

## Completion in `f062dc7d0`

Each normal worker exit supplies the ownership of the value it actually returns.
A direct join uses the same possible mutex release order for that result and the
contents left in the vector. The native join-success proof still depends on the
worker’s checked normal execution. Joining a worker that returns an empty pop yields `Ok(None)`.

The source regressions in
`source/rust_verify_test/tests/resource/memory/synchronization/shared_payloads/joined.rs`
establish these local byte bounds. Each accepts the listed bound and rejects one
byte less.

| Source observation | Model bytes |
| --- | ---: |
| Consumer holds the guard and the popped `Option<Box<[u8; 32]>>` | 106 |
| Completed worker retains its result while the waiting caller holds a 256-byte array | 372 |
| Caller retains the result after dropping the last mutex owner | 41 |
| Empty pop after dropping the last mutex owner | 9 |
| Two consumers retain their results from a single published box | 50 |
| Unique extraction and the returned nested vector are both live | 171 |
| Only the result remains, with an inner reservation of 61 or 3 bytes | 94 or 36 |

Dropping the last result proves zero live bytes in the caller. A checkpoint
while another writer is outstanding and a returned value with an unresolved
mutex history are both rejected. The total concurrent peak remains open in 07.
