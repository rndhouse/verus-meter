# 03.4.2.7. Track independently live aliases to a worker's inner Arc

The [ownership audit](03.4.2-audit-loops-and-shared-ownership.md) identified this source case. A publisher can keep a clone of a fresh inner
`Arc<Vec<u8>>` while moving the original inside an outer `Arc` and sending
the outer to a worker. Both references keep one inner allocation alive. The
outer allocation has its own lifetime and byte cost.

## Reproduce

Start with `nested_buffers()` in
`source/rust_verify_test/tests/resource/memory/worker_shared_ownership/occurrences/payloads.rs`.
On each iteration, bind `let keep = root.clone();` immediately before wrapping
`root`. Put `drop(keep);` immediately after `handles.push(job);`. At
`fc48a9f79`, the push reports “carrying a nested Arc with an independently live
alias”. Moving only the drop to immediately before the push proves the local
bounds. Both source orders are within the [approved strong-Arc operations](../../../concurrent-model.md#supported-operation-matrix).

## Required behavior

- [x] Record the worker's claim on the actual inner allocation from that
  iteration. While both handles exist, count the inner backing once and account
  separately for the outer wrapper and each live handle.
- [x] Support both last-owner orders. Drop the publisher's clone while the
  worker is outstanding. Also join and drop the outer while the publisher's
  clone still owns the inner. Test a live-byte checkpoint between the drops
  and verify release after the last one.
- [x] Preserve the claim across loop back edges and partial collection. Use two
  visits to show that dropping a handle from one cannot retire the other's
  backing. Check exact bounds and one-byte failures, including the original
  two-worker, 19-byte case after the local clones drop.
- [x] Keep the existing tests for private nested storage, shared pre-loop roots,
  and nonunique outer extraction passing. Run the [applicable checks](../README.md#validation)
  and record the feature revision and named regressions in the ownership audit.

Start at `pack_occurrence_backing` in
`source/vir/src/resource/memory/workers/shared/carried.rs`. Its outstanding
alias check prevents private storage from moving wholesale into a worker slot
while another owner can still use it. Review the per-visit reservations in
`workers/shared/peers.rs` and `workers/shared/deferred.rs` under the same
memory module. A worker carrying a wrapper also owns the wrapper's bytes while
its claim on the inner backing is outstanding. Preserve both obligations through
publication, waiting, result delivery and destruction.

## Completion evidence

Feature commit `ed750de2f` retains the selected inner allocation through either drop order. The publisher-first, worker-first and crossed-visit regressions are named in the [ownership audit](03.4.2-audit-loops-and-shared-ownership.md#findings). `912e3b298` also checks that explicit final joins consume the entire generated collection.
