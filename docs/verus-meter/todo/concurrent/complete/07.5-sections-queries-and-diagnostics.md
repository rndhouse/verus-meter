## Implementation and validation

Feature commit `63e037889` checks scoped obligations against the same worker
phases as a total bound. The following cases run through the ordinary verifier in
`source/rust_verify_test/tests/resource/memory/concurrent_scopes.rs`.

- An outstanding child can require 289 bytes. After join, a zero-byte current
  bound passes, while a 288-byte peak still fails. Branches and earlier loop
  iterations contribute only where their histories reach the checkpoint.
- A section pays for its own children, and the enclosing scope pays the section
  allowance alongside its live frame. Returning before a counted drain finishes
  fails at the section exit. Returning after the drain passes.
- A worker holding an incoming shared backing alongside a child needs 321 bytes
  and rejects 320. Inside a newly opened section the incoming backing belongs
  to its parent, and the child alone still requires 289 bytes. Distinct mutexes
  invalidate a checkpoint that relies on exclusion by the same instance.

Sections that publish workers need a fixed byte bound. An unbudgeted worker
cannot refer to its publisher's peak history. A worker cost that cannot be
proved in its source scope or transferred to its observer can still leave the
total unproved. The verifier identifies the missing evidence or emits the
failed byte obligation. Successful export requires verification of worker bodies.

The prepared runtime test compiled and ran the declared `n + 512` query.
Runtime evaluation uses the existing size-query grammar. The rebuilt verifier passed
1,270 memory integration tests, 47 resource examples and 251 upstream concurrency
tests. The 88 memory unit tests, formatting and Clippy also passed. One unit
test and one upstream test were ignored by their suites.
