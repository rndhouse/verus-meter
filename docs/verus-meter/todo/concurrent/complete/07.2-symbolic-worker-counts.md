# 07.2. Symbolic worker counts

Dependencies: 07.1.

## Work

- [x] Lift the fixed-worker proof to counts of workers in a finite set of phases. Derive
  counts from actual spawn, wait, completion and join events, including loops that publish
  or drain handles. Establish initial counts and prove preservation and nonnegativity when
  one worker or its caller steps.
- [x] Relate the number spawned, still running and completed with an outstanding result. A
  completed worker can stop contributing scratch while its result and handle remain live.
  Charge a shared allocation according to its identity across all occurrences.
- [x] Preserve symbolic sizes and phase correlations through the loop proof. Use
  mathematical integers for internal sums and prove source budget arithmetic fits the
  existing `u64` rules. Keep the source expression grammar. Allow ordinary checked
  invariants and numeric lemmas when arithmetic needs help.

## Completion and validation

Verify total bounds on the same spawn/join loop with symbolic `n` and `b`. Its scratch
contribution is at most `n * b` without synchronization, and at most `if n == 0 { 0 } else
{ b }` with one shared mutex. Exercise zero, one and many workers and a loop that joins
before spawning the next worker, where scratch can be reused. Check a too-small bound on a
reachable overlap and an overflowing source budget. The proof must cover arbitrary
admitted counts without enumerating schedules or requiring a user-maintained count of
allocations.

## Implementation and validation

Feature commit `4f8b1d0c1` covers a counted loop that publishes one worker
family and joins its handles. The verifier increments its own count on spawn,
decrements it on join and proves its relationship to the handle vectors at each
loop boundary. Wait and completion keep the handle outstanding. A completed
worker contributes its inline result until collection. Mutual exclusion limits
the number of workers in guarded phases only for the same mutex instance.

The executable regressions in `source/rust_verify_test/tests/resource/memory/counted_workers.rs`
verify the same symbolic loop with unrestricted and mutex-protected scratch.
They check zero, one and 50,000 workers, immediate joins, reuse after draining,
overlap on different locks, an inclusive loop's extra visit and overflowing
budget arithmetic. Returning a `u64` adds eight bytes per outstanding result.
All 1,254 memory integration tests and 47 resource examples passed.

The loop comparison supplies a candidate ceiling that must hold at every spawn.
Compound expressions containing spawn or join can use that ceiling for their
intermediate states. [07.4](07.4-helpers-and-retained-storage.md) covers heterogeneous fixed workers and results that own allocations.
