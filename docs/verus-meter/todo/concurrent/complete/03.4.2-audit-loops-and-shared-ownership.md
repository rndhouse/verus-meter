# 03.4.2. Audit loops and shared ownership

**Second child of [03.4](../03.4-worker-integration-and-completion.md).** Use the
[03.3 evidence](03.3-symbolic-populations-and-shared-ownership.md)
to check that symbolic worker counts and shared allocation lifetimes follow
actual spawns, joins, clones and drops.

## Findings

- [x] **Inline and named drops.** Before `58dda5e45`, accounting scheduled the temporary `Arc`’s destruction proof before its join operand’s proof actions and omitted the drop from the ownership summary. The named form recorded both events. `heap.rs` now schedules destruction after the operand and records the same checked drop. In `every_peer_of_the_same_visit_must_retire`, both forms prove 248 live bytes while the last sibling still owns the newer backing. Both reject 247 at that checkpoint at the default solver limit.
- [x] **Backings that survive a loop iteration.** [Separate drains](03.4.2.1-carry-peer-backings-through-loops.md) verify in `3a458c62c`. [Joining during publication](03.4.2.2-join-during-peer-publication.md) verifies in `8e4dde1f8`. Both source forms count earlier buffers at the next loop head and release each backing after its own last peer. The vector-slot form also retains capacity acquired by the push.
- [x] **Publication and membership.** `workers/populations.rs` stores each publication's descriptor with its handle. `loops/populations.rs` checks membership against the actual collection on entry and each back edge. `fresh_buffers_charge_each_outstanding_visit` covers zero visits and two equal-sized, independently allocated buffers. `repeated_constructions_bind_each_source_iteration` varies the captured capacity. `mixed_worker_batches_preserve_each_result_during_partial_collection` drains to a symbolic remainder. `a_worker_receives_and_drains_an_entire_symbolic_collection` transfers the obligation to another worker. `mixed_arc_drain_rejects_a_fictitious_worker` rejects a count unsupported by the actual pushes.
- [x] **Release and excluded paths.** `workers/shared/occurrences.rs` freezes the selected allocation identity. `workers/shared/peers.rs` retires reservations against that identity. `an_equal_sized_buffer_from_another_visit_cannot_take_the_charge` rejects a one-byte reduction after dropping a peer from a different visit. `symbolic_collection_releases_duplicate_inner_links_once` and `a_symbolic_result_vector_retains_the_payload_until_its_last_alias_drops` exercise nested ownership and stored results. `joined_strong_ownership_rejects_weak_raw_and_leaking_exits` rejects `Arc::downgrade`, `Arc::into_raw` and `mem::forget` at the unsupported operations. `a_worker_cannot_justify_final_release_for_a_strong_cycle` is rejected at the recursive layout. These last four programs stop before a memory proof can accept them. The new rejection tests are in `22dc17094`.

- [x] **A collector fully drains shared handle vectors.** [03.4.2.3](03.4.2.3-join-shared-collections-in-a-worker.md) verifies at `f4faebc4e`. The publisher retains each canonical backing through join, including references in fixed nested payloads. Other handles keep their own references. See `collecting_worker_drains_symbolic_mixed_arc_results`, `collecting_one_vector_keeps_the_siblings_shared_backing` and `publisher_can_drop_its_last_fixed_alias_before_collecting`.
- [x] **Ownership survives the collecting worker.** In `957857b33`, `collector_returns_the_remaining_handle_slots` and `collected_arc_keeps_the_selected_workers_result_identity` prove which references survive a partial drain. In `c7bcde2bb`, `a_forwarded_carrier_keeps_its_original_visit` checks both a consuming receiver and a returning receiver against the original allocation visit. See [03.4.2.4](03.4.2.4-transfer-surviving-shared-ownership.md).
- [x] **Ownership inside a repeated allocation.** [03.4.2.5](03.4.2.5-preserve-repeated-payload-ownership.md) closed at `2cf864351`. Two fresh buffers contribute independently. Two wrappers can retain one pre-loop backing through separate joins and drops. The closed-consumer and embedded-job tests check the original paying frame and the selected worker's actual result.
- [x] **Unique extraction after join.** Both cases from the final review use [supported strong-Arc operations](../../../concurrent-model.md#supported-operation-matrix). [03.4.2.6](03.4.2.6-extract-a-joined-inner-arc.md) closed the extraction case at `fc48a9f79`. The selected worker preserves the actual inner identity. The verifier releases the 24-byte wrapper, proves 73 live bytes with the inner buffer, and rejects 72 or a nonunique outer.
- [x] **A publisher clone survives publication.** In `ed750de2f`, `the_publisher_can_release_its_clone_after_storing_the_worker` proves 214 bytes after the publisher drops its clone and 97 with one joined wrapper left. `dropping_the_joined_wrapper_keeps_the_publishers_clone_live` proves 113 bytes when the publisher is the last owner, including when the worker consumed the wrapper. `dropping_wrappers_from_different_visits_keeps_both_inner_buffers` proves 259 bytes while two distinct buffers remain live and 168 after one is released. All three reject one-byte shortfalls. See [03.4.2.7](03.4.2.7-track-independent-inner-aliases.md).
- [x] **Explicit final joins.** At `912e3b298`, `explicit_pops_must_consume_every_published_worker` proves that two explicit pops from each two-entry vector consume all four handles. Omitting the final join fails both the lost-handle check and the final byte checkpoint.

Source paths above are under `source/vir/src/resource/memory/`. The regressions
live under `source/rust_verify_test/tests/resource/memory/`. Positive concurrent
cases verify local byte obligations and still produce the required global
peak diagnostic.
