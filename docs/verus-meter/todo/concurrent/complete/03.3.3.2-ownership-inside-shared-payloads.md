# 03.3.3.2. Ownership inside shared payloads

**Completed under [03.3.3 — Prove final release](03.3.3-shared-final-release.md).** Dropping the last outer `Arc` destroys its payload. An inner buffer can still have an owner elsewhere, and a worker whose handle was stored in the payload can still be running. The analysis follows these owners through the supported handle and result collections.

## Work

- [x] Preserve ownership of a buffer supplied by a caller, including across helper calls, worker captures, collection slots and returned results. Follow the existing convention for incoming storage so the same buffer is charged once and its release is visible in the domain that pays for it.
- [x] Track the strong handles in each supported acyclic payload. Two fields may point to the same inner allocation. Destroying the payload drops both handles, and releases the inner backing only when its own last strong handle drops. Preserve its identity for later synchronization proofs.
- [x] Carry the join obligation of a worker handle inside a payload through supported transfers. Dropping the payload while it still owns an outstanding handle must produce the detached-worker diagnostic. A checked join must account for any storage retained by its result.

## Done when

Use executable allocations, clones, moves, joins and drops. Move aliases of an outer `Arc` into workers, store their join handles in a vector, and follow the payload through the joins and final drop. Exercise a caller-supplied buffer and a payload with two fields pointing to the same inner buffer. Check the tight live total and the drop in bytes after final release. Keep one extra inner clone outside the payload and require the early-release claim to fail. Include a case where a worker performs the last drop before its own join, and check the parent's 89-byte versus 88-byte vector-plus-box case.

Exercise both a transferred worker handle that reaches its join and an outstanding handle lost at destruction. At the default solver limit, require the relevant byte or ownership diagnostic for each negative case. Positive cases must discharge the local obligations needed by 07. The parent's exclusions for weak references, raw ownership, cycles and unmodeled reclamation still apply.

## Implementation and validation

Feature commit `998b806a0` preserves the original payload when an allocation created before the publishing loop passes through workers, join-handle slots and result slots. A join checks which allocation the worker returned. For a result vector containing aliases of that one allocation, the verifier proves that each push adds one reference. Final destruction uses the same ownership tree that recorded the original buffer, inner handles and job.

| Source program | Verified local result at the default solver limit |
| --- | --- |
| A helper takes a 100-byte caller buffer and distributes its outer handles to workers | The helper accounts for 48 bytes at its final-handle checkpoint. The equivalent allocating frame accounts for 148. The caller proves a 612-byte budget across the call and can reuse it on return. A 611-byte budget fails at the call. |
| Two fields point to the same 19-byte inner buffer | For symbolic `n > 0`, the collector can keep all `n` results, pop one, and drop the rest. With the last handle, its payload and the loop scalars still live, the total is 103 bytes. Dropping the handle leaves 4. A 102-byte claim fails. A surviving inner clone keeps the total at 71 after the outer drop. A separate case covers zero workers. |
| A worker drops the collected handle before its own join | Its checkpoint falls from 99 bytes to 8. A surviving inner clone or an outer alias still held by an unjoined peer defeats the 8-byte claim. |
| One payload owns a vector and a box | With one handle left, 89 bytes pass and 88 fail. Dropping the final handle leaves zero. |
| The payload owns a worker that returns a buffer | Proved uniqueness allows `Arc::into_inner` to recover the handle from a stored result. Joining it accounts for 48 bytes and rejects 47. Losing it produces the detached-worker diagnostic. A second local or stored alias prevents early extraction. |

The new caller case covers a by-value consumer that joins its workers and destroys the entire supplied payload before returning unit. A mixed result whose inner ownership graph is unresolved can also prevent a worker checkpoint from proving a tighter bound.
