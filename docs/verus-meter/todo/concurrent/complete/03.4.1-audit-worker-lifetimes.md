# 03.4.1. Audit worker lifetimes

**First child of [03.4](../03.4-worker-integration-and-completion.md).** Trace
standard Rust and vstd spawn/join from the source closure through the checked
worker body and back to the caller. Start with the evidence from
[03.1](03.1-closure-invocation-and-cleanup.md) and
[03.2](03.2-executable-worker-analysis.md).

## Work

- [x] Map the lifecycle and invocation requirements in 03 and the operation matrix to production paths and named tests. Check source capture, invocation and destructor semantics across supported closure forms. Check that they work independently of the compiler’s generated wrapper shape.
- [x] Follow construction, publication, execution, waiting, completion and result delivery. Identify who pays for inline values, backing allocations, completion records and temporaries at each stage. Cover a worker completing before spawn returns and a caller waiting while its own storage stays live.
- [x] Trace nested workers and transferred handles. Check parent and worker identity, construction-time capture values and projections, branch ordering, and allocation and synchronization identities across the supported calls and thread boundaries. At each accounting exit, check that a descendant has been joined once or that its outstanding join obligation follows the transferred handle.
- [x] Check native and vstd outcomes against the panic-free proofs and environmental assumptions from 01. Exercise lost handles, unsupported captures and missing worker summaries. Confirm that Rust’s `Send` and `Sync` checks still apply and that successful join requires evidence.

## Evidence

Audited feature revision `ff796eeea`. All byte counts below are source-model bytes.
These source tests run the verifier through its normal entry point. For a valid
local obligation, they expect only the diagnostic for the outstanding global
peak proof. Each deliberately short bound must produce an additional diagnostic
at the affected lifecycle stage.

| Requirement | Production path and observed source regression |
| --- | --- |
| Capture and invocation | The Rust frontend's `resource/memory/concurrency.rs` records executable captures, field projections, closure kind and the original body. VIR's `concurrency/invocation.rs` and `workers/body.rs` check those facts against the transferred environment. `source_worker_invocation_distinguishes_borrowed_and_owned_environments` exercises both ways a move closure can use its environment. `partial_capture_transfers_only_the_selected_child_owner` and `erased_noncopy_proof_capture_cannot_hide_executable_closure_copies` distinguish runtime fields from untouched siblings and erased proof data. |
| Destruction and early exits | `workers/execution.rs` applies each normal exit's body effects, then `workers/body.rs` checks the remaining capture ownership while the result is live. Explicit moves and drops follow the source body. Implicit destruction supplies no ordering proof between remaining captures. `conditional_allocations_and_early_returns_preserve_capture_cleanup` and `early_return_in_a_borrowed_body_does_not_change_owned_capture_destruction` exercise branch-specific cleanup. The check uses the original receiver and projections and has no dependency on the generated invocation wrapper's shape. |
| Construction and publication | `workers.rs` publishes the captured storage and `workers/inputs.rs` binds the values saved at construction. In `outgoing_sizes_use_construction_values_after_parent_mutation`, changing a caller variable after constructing the closure leaves the original capacity charge intact. In `a_worker_can_complete_before_spawn_returns`, the publisher's buffer can coexist with the worker's 64-byte temporary or completed result. Reducing the taken branch's allowance by one byte fails at spawn. The branch that skips spawn needs no completion record. |
| Waiting, completion and collection | `workers/states.rs` retains the waiting caller's frame and the completed worker's result. `collect_worker_result` in `workers.rs` transfers the result to the actual joiner. In `waiting_worker_keeps_its_buffer_until_the_joiner_drops_it`, the inner join accounts for an 88-byte vector, an 8-byte handle, two one-byte completion tags and a 48-byte child result. Increasing the vector capacity by one fails the 146-byte obligation. After the outer join, 88 bytes remain until the vector is dropped. A bound of 87 fails there. |
| Worker identity and descendant obligations | `workers/identity.rs` identifies publications by their enclosing worker, site, closure definition and occurrence. `workers.rs` transfers join responsibility with the actual captured handle and checks closure of the worker domain. `workers/waits.rs` binds the waiter to its target and consumes each result once. `nested_workers_join_their_actual_children` and `native_helper_forwards_the_selected_worker_with_its_owned_result` exercise the nested and helper paths. `transferring_a_handle_cannot_hide_detach_in_its_receiver` and `nested_workers_cannot_discard_unjoined_descendants` reject lost obligations. A separate VIR test, `join_waits_reject_cycles_and_resume_only_the_actual_waiting_actor`, checks the cycle guard directly. |
| Shared mutex identity | `workers/execution.rs` retains the worker body's synchronization flow and entry bindings. `workers/outputs.rs` carries ownership and shared backing identity through the returned value. In `relayed_join_keeps_the_same_mutex_allocation`, a vstd worker collects a native worker's returned `Arc<Mutex<u64>>`. Two handles to the same allocation occupy 49 bytes after both joins. Changing only which equally sized mutex the caller retained raises that to 82 bytes and the 49-byte assertion fails. Both cases reach zero after the final drops. |
| Outcomes and rejected programs | `workers/results.rs` ties successful extraction to the recognized join and checked worker. Allocation and thread creation success are environmental assumptions. User panic freedom and spawn preconditions are proof obligations. `both_spawn_apis_require_the_workers_precondition` removes the caller's precondition and fails at spawn for both APIs. `failed_worker_correctness_cannot_establish_join_success` exposes a worker overflow. `both_join_apis_preserve_verified_payload_postconditions` checks the delivered payload. `ordinary_result_cannot_fabricate_a_success_witness` and `a_caller_requires_a_completed_callee_summary` exercise missing evidence. |
| Rust and Verus admission checks | `native_spawn_preserves_rust_send_checks` rejects a non-`Send` capture. `vstd_spawn_requires_a_sync_payload_in_a_shared_handle` rejects `Arc<Cell<u64>>`. `consuming_a_capture_does_not_admit_a_non_move_worker` rejects an implicitly by-value closure outside the supported explicit-`move` domain. Verus also rejects mutable-reference captures before worker accounting, as covered by the upstream `disallowed_mut_capture1` test. |

## Scope and validation

The mutex regression establishes the identity of the allocation containing the
mutex. Proving that a scratch buffer's **whole lifetime** lies inside an acquisition
of that instance belongs to [04](../04-allocation-and-synchronization-lifetimes.md).
[05](../05-function-and-worker-summaries.md) composes those facts through general
helpers. [07](../07-symbolic-concurrent-bound-composition.md) owns the simultaneous
peak proof. The phase checks above establish local obligations that feed that proof.

The release verifier build, test-package formatting and resource-test Clippy passed.
The focused source suites passed with 42 concurrency, 30 worker execution, 5 worker
helper, 31 worker population and 9 synchronization tests. All 15 worker unit tests
passed. The upstream executable-closure suite passed 111 tests with one ignored.
The audit added four source regressions and required no production change. The
integrated validation for closing 03 remains in [03.4.3](../03.4.3-validate-and-close-03.md).
