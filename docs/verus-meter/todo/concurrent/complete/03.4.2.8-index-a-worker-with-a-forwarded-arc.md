# 03.4.2.8. Index a worker with a forwarded Arc

**Complete on the implementation branch at `ae99a40fa`.** The [surviving
ownership audit](03.4.2.4-transfer-surviving-shared-ownership.md) originally
stopped at a second vector. A receiver's join handle can now enter that vector
while a sibling worker still owns a share of the same allocation.

- [x] Publish the receiver's whole local group of strong handles. Charge the
  original allocation once. Use the selected worker's recorded capture or
  return value to identify the allocation visit, including across another pop.
- [x] Check both final-owner orders, a worker returning the alias, and a vector
  containing two relays from different visits to the same constructor. Reject
  a missing join and a one-byte shortfall. Preserve the global contract gate.

The source regressions are in
`source/rust_verify_test/tests/resource/memory/worker_shared_ownership/occurrences/handoff/relay.rs`.
With two equal-sized allocations, the tests establish 239 bytes while the last
owner is in the second vector and 147 after its join and vector drop. In the
two-slot test, joining the older relay leaves both allocations live at 246
bytes. The verifier rejects 245 and proves 186 after the older peer ends.
A separate case keeps the returned alias live at 230 bytes and rejects 229.
The publisher must still own the backing's accounting scope. Splitting the
same finite group among separate indexed receivers remains unsupported.
