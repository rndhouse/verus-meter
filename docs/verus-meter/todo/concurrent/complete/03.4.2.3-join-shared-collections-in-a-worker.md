# 03.4.2.3. Join shared handle collections in a worker

A publisher moves a vector of outstanding handles into a collecting worker.
Each original worker may own references to one or more existing shared roots.
The collector joins every handle, drops any returned aliases and returns unit
or an inline scalar. The publisher can still own other handles to those roots.

- [x] Keep one backing charge per canonical allocation while the collector can
  own references. Derive its share from actual captured slots and worker
  descriptions. Reconcile that share exactly once when the collector is joined.
- [x] Verify the original one-handle and symbolic mixed-family cases. Check
  zero workers, a final drop, retained siblings and a lost join. Require a
  one-byte-short claim to fail locally.
- [x] Keep worker checkpoint storage, caller/target identity and the global
  proof gate intact. Run the applicable memory checks. Record the revision in
  the [ownership audit](03.4.2-audit-loops-and-shared-ownership.md).

## Evidence

Feature revision `f4faebc4e` records the number of references to each allocation
in the actual captured slots. The verifier checks the selected worker at each
join, verifies empty discarded handle vectors and checks that locally returned
aliases end before the collector exits. The publisher retires the captured
share at the matching collector join.

In `worker_shared_ownership/collections.rs`, the symbolic drain covers an empty
vector and workers returning one or two distinct roots. The sibling test proves
81 bytes inside the collector and 57 in the publisher after join. Both claims
fail one byte lower. The nested-Arc case also checks that dropping the
publisher's last fixed handle leaves 57 bytes before join and zero afterward.
All positive cases reach the required global-proof diagnostic.
