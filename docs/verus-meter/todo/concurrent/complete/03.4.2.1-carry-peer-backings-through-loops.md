# 03.4.2.1. Carry peer-owned allocations through loop iterations

Part of [03.4.2](../03.4.2-audit-loops-and-shared-ownership.md). A publication
loop allocates one buffer per visit and sends strong handles to two workers.
One drain joins and drops all carrying results. A later drain joins the peers.
The approved thread and strong-ownership operations cover this program.

- [x] Charge every surviving backing at the loop head, during join and at exit.
  Replace the empty-at-entry requirement for an allocation handed off during a drain.
  Prove candidate bounds at entry and on the back edge, using the actual drops,
  allocation identities and collection contents.
- [x] Compare draining the peer within the iteration to draining it in the later
  loop. With two visits and 19-byte buffers, both 59-byte backings survive the
  first split drain. The 206-byte checkpoint must verify and 205 must fail.
  Cover zero visits and the final peer release. Keep the global proof gate.
- [x] Exercise both source forms at the default solver limit and retain the
  equal-sized, distinct-visit regressions. Run the applicable memory checks
  and record the tested revision before closing the parent audit.

## Evidence

In `peer_backing_survives_until_its_own_drain`, the number of workers and the
buffer capacity are symbolic. The two-visit, 19-byte example distinguishes
these checkpoints at the default solver limit.

| Point in the program | Live storage in bytes | Checked outcome |
| --- | ---: | --- |
| Both workers carrying the backings have been joined, both peers survive | 206 | 205 fails |
| Last iteration of the paired drain, one peer survives | 146 | 145 fails |
| Both drains finished, vector capacity still reserved | 86 in the paired case | The final vector drops leave only the six scalar bytes |

The 86 bytes comprise six scalar bytes, two 24-byte vector headers and four
reserved 8-byte handle slots. Each surviving peer adds a one-byte completion
tag and one 59-byte backing (16-byte control block, 24-byte vector, 19-byte
buffer). With zero publications both drain loops can be skipped. Final release
is checked through the source drops.

The publisher installs a charge before taking the drain's loop-head snapshot.
`loops/deferred.rs` proposes a checked bound on the sum of backings in carrying
handle slots and backings retained for peers. A separate equality accounts for
the occupied peer slots' tags. Verus checks these relationships on entry and
the back edge. `finish_peer_bound` in vstd proves how a retirement can affect
the sum. A retiring peer uses the allocation's full visit identity, so equal
extents cannot justify releasing another visit. The new lemma is activated
only in a loop that uses the sum.
