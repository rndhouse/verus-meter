# 03.3.1. Preserve ownership across transfers

**Completed on the implementation branch in `06a1e3c73` and `c324acdb8`.** When a join handle, worker collection or returned alias moves to a helper or another thread, the receiver must get the exact worker or allocation identity, the references it now owns, and any outstanding join obligation. Existing collection transfers and local moves of returned aliases are the starting point.

## Work

- [x] Carry the selected worker's checked inputs, possible outcomes and shared references through supported helper calls and worker captures/returns, including native joins and owning results. Preserve the backing of transferred collections and the outstanding members of a partially drained collection.
- [x] Keep distinct dynamic visits to the same join site distinguishable while earlier results survive. Substitute the actual caller, nested parent and loop occurrence in scalar snapshots, aggregate views and ownership descriptors. Cover repeated publications and captured collections whose construction depends on the enclosing occurrence.
- [x] Check who may join each worker after transfer in an acyclic worker tree. Preserve descendant obligations across scope exit. Reject detach, lost descendants and self or cyclic waits.

## Done when

Pass a handle from a mixed collection to another worker or helper, join it there and return its selected alias. Keep two results from the same join site alive at once. Prove that each still refers to its own buffer and that a local move or clone preserves its identity. Swapping the selected buffer must break a bound that fits only the smaller one.

For a helper returning a collection drained to `keep <= n`, verify the caller's complete drain. Changing its condition from `rest.len() > 0` to `rest.len() > 1` must report the outstanding handle at cleanup at the default solver limit. Exercise a stale capture substitution, a foreign allocation and a lost or cyclic join as negative cases.

## Validation

Two workers return shared buffers with capacities of 7 and 19 bytes. The same join statement runs twice and both results stay live in a vector. After the other owners drop, the smaller buffer and its one remaining handle fit in 55 model bytes. Keeping the larger buffer breaks that bound. Moving a result, storing a clone and dropping the original, and dropping a vector that still contains a result all pass their local byte checks.

The source regressions also forward native handles through a helper, transfer a popped handle to a worker, and finish joining a collection that a helper returned with exactly `keep` handles. Returning a foreign allocation breaks the byte bound. Leaving a handle unjoined fails cleanup. A nested worker using a captured handle vector returns 7 bytes on its first visit and 201 on the next. Applying the first visit’s bound to the second fails. Cycle and self-wait checks run in the worker wait-state unit tests.
