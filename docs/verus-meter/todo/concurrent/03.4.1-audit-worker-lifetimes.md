# 03.4.1. Audit worker lifetimes

**First child of [03.4](03.4-worker-integration-and-completion.md).** Trace
standard Rust and vstd spawn/join from the source closure through the checked
worker body and back to the caller. Start with the evidence from
[03.1](complete/03.1-closure-invocation-and-cleanup.md) and
[03.2](complete/03.2-executable-worker-analysis.md).

## Work

- [ ] Map the lifecycle and invocation requirements in 03 and the operation matrix to production paths and named tests. Check source capture, invocation and destructor semantics across supported closure forms. Check that they work independently of the compiler’s generated wrapper shape.
- [ ] Follow construction, publication, execution, waiting, completion and result delivery. Identify who pays for inline values, backing allocations, completion records and temporaries at each stage. Cover a worker completing before spawn returns and a caller waiting while its own storage stays live.
- [ ] Trace nested workers and transferred handles. Check parent and worker identity, construction-time capture values and projections, branch ordering, and allocation and synchronization identities across the supported calls and thread boundaries. At each accounting exit, check that a descendant has been joined once or that its outstanding join obligation follows the transferred handle.
- [ ] Check native and vstd outcomes against the panic-free proofs and environmental assumptions from 01. Exercise lost handles, unsupported captures and missing worker summaries. Confirm that Rust’s `Send` and `Sync` checks still apply and that successful join requires evidence.

## Done when

Each lifecycle requirement has a source test that reaches the production check.
Use existing mutations or add focused variants where coverage is missing. For
example, retaining a capture or allocating while waiting should change the byte
obligation, and losing a handle should produce its own diagnostic. Record the
tested revision and results. Keep any required fixes linked and open until verified.

Start in `source/vir/src/resource/memory/workers.rs` and
`source/rust_verify_test/tests/resource/memory/worker_execution.rs`.
The tests `a_worker_can_complete_before_spawn_returns` and
`waiting_worker_keeps_its_buffer_until_the_joiner_drops_it` cover two useful
lifetime boundaries.
