# 03.4.2.5. Preserve ownership inside repeatedly allocated shared payloads

In `fresh_buffers_charge_each_outstanding_visit`, wrap the fresh
`Arc<Vec<u8>>` in another `Arc` before sending it to its worker. With a
generous budget the executable `handles.push(job)` at revision `8e4dde1f8`
rejects an “indexed Arc payload with incoming storage or nested reference
lifetimes”. The structure is acyclic and every handle has a destructor.

- [ ] Carry the inner ownership description with the outer allocation's full
  visit identity. Cover a locally owned buffer, incoming storage, two inner
  aliases and an embedded join handle. Keep the input charged to its caller.
- [ ] Compare distinct inner allocations with two outer allocations sharing
  one inner root. Hold an independent alias through the outer drop. Verify
  final release, reject a premature one-byte reduction and retain the lost-job
  rejection when the payload still owns a worker handle.
- [ ] Run the applicable checks and record the revision in the
  [ownership audit](03.4.2-audit-loops-and-shared-ownership.md). Reuse the
  existing fixed-payload tests in `worker_shared_ownership/payloads.rs` as
  controls for the repeated-site cases.
