# 03.4.2.3. Join shared handle collections in a worker

A publisher moves a vector of outstanding handles into a collecting worker.
Each original worker may own references to one or more existing shared roots.
The collector joins every handle, drops any returned aliases and returns unit
or an inline scalar. The publisher can still own other handles to those roots.

- [ ] Keep one backing charge per canonical allocation while the collector can
  own references. Derive its share from actual captured slots and worker
  descriptions. Reconcile that share exactly once when the collector is joined.
- [ ] Verify the existing one-handle and symbolic mixed-family programs
  `a_receiving_actor_cannot_discharge_its_publishers_indexed_shared_claims`
  and `receiving_a_mixed_arc_result_requires_its_publishers_claim`. Both
  currently reject at the receiver's join. Check zero workers, a final drop,
  retained siblings and a lost join. A one-byte-short claim must fail locally.
- [ ] Keep worker checkpoint storage, caller/target identity and the global
  proof gate intact. Run the applicable memory checks. Record the revision in
  the [ownership audit](03.4.2-audit-loops-and-shared-ownership.md).

Start with `workers/shared.rs`, `workers/populations.rs` and the existing
capture bindings in `workers/execution.rs` under `source/vir/src/resource/memory/`.
